# Mesh Radio Bot 📻

Веб-интерфейс и бот для Meshtastic. Подключайте ноду по **USB или Bluetooth**, общайтесь в каналах и личке, храните историю в **SQLite** и настраивайте ответы на личные сообщения.

> [!NOTE]
> Это проект сообщества, а не официальный клиент Meshtastic. Веб-интерфейс работает по HTTP: используйте его в доверенной локальной сети и не открывайте порт напрямую в интернете.

### Быстрый маршрут

1. Подготовьте ноду с антенной и правильно выбранным регионом.
2. Выберите [запуск через Docker Compose](#запуск-через-docker-compose) или [без Docker](#запуск-без-docker).
3. [Подключите ноду](#подключение-ноды) в веб-интерфейсе.
4. Откройте [чаты](#чаты-и-каналы) или настройте [бота](#команды-бота).

## Возможности

| Раздел | Возможности |
| --- | --- |
| Чаты | Общий канал LongFast, дополнительные каналы и личные диалоги; отправка, цитирование, реакции и поиск эмодзи |
| История | SQLite, счётчики непрочитанных, статусы доставки, импорт доступных сообщений после переподключения |
| Ноды | Поиск, карточки с телеметрией, координатами и качеством связи, карта и история трассировок |
| Бот | Шаблоны «запрос → ответ», команды ping/p, trace, stats, w и date; отвечает только в личке |
| Радио | Подключение по USB или BLE, просмотр и изменение поддерживаемых настроек ноды и каналов |
| Веб-интерфейс | Вкладки «Дашборд», «Чаты», «Настройки», адаптивная мобильная версия, вход по логину и паролю |

**Стек:** Python 3.13 · Meshtastic Python 2.7.11 · `http.server` · `sqlite3` · JavaScript без сборщика · Leaflet 1.9.4 · Docker Compose. Сервер — [`app.py`](app.py), клиент — [`app.js`](app.js) и [`index.html`](index.html).

## Требования

- Raspberry Pi с 64-битной Linux-системой; Docker Engine и плагин Docker Compose нужны только для запуска в контейнере.
- Для запуска без контейнера: Python 3.13, модуль `venv` и доступ к `pip`.
- Нода Meshtastic с настроенным регионом и антенной. Перед включением передачи убедитесь, что регион в ноде выбран правильно.
- Для USB: кабель передачи данных и последовательный порт вида `/dev/serial/by-id/...` или `/dev/ttyACM0`.
- Для BLE: работающий Bluetooth и BlueZ на хосте.
- Для погоды: исходящий HTTPS-доступ с Pi к `wttr.in`. Для подложки карты браузеру нужен доступ к OpenStreetMap.

Проверка Docker на Pi:

```bash
docker --version
docker compose version
```

Обе команды должны вывести версии. Если команда не найдена, установите Docker Engine и Compose для вашей системы перед запуском проекта. Если у пользователя нет доступа к Docker, добавьте `sudo` перед каждой командой `docker compose` ниже.

## Запуск через Docker Compose

В каталоге проекта создайте личную конфигурацию и задайте пароль:

```bash
cp .env.example .env
chmod 600 .env
nano .env
```

`cp` создаёт конфигурацию из образца; `chmod 600` ограничивает доступ к ней; `nano` открывает файл для редактирования. Замените `WEB_PASSWORD` на длинный случайный пароль, настройте город и часовой пояс. Пароль можно создать командой `openssl rand -base64 32`. Файл `.env` исключён из Git и Docker build context.

Запустите сервис:

```bash
docker compose config --quiet
docker compose up -d --build
docker compose ps
```

`config --quiet` проверяет конфигурацию без вывода пароля; `up -d --build` собирает образ и запускает контейнер; `ps` должен показать сервис `meshtastic` со статусом `Up` и портом `8766 → 8765`. Откройте в браузере устройство в той же локальной сети:

```text
http://<IP-АДРЕС-СЕРВЕРА>:8766/
```

Введите `WEB_USER` и `WEB_PASSWORD` из своего `.env`. Порт `8766` меняется через `MESHTASTIC_WEB_PORT`.

### Переменные окружения

| Переменная | Назначение |
| --- | --- |
| `WEB_USER`, `WEB_PASSWORD` | Учётная запись для HTTP Basic Auth; пароль обязательно замените |
| `MESHTASTIC_WEB_PORT` | Порт на Pi для браузера, по умолчанию 8766 |
| `WEB_HOST`, `WEB_PORT` | Адрес и порт при запуске Python напрямую; в Compose задаются контейнером |
| `DB_PATH` | Путь к SQLite при прямом запуске; в Compose база хранится в томе |
| `PYTHON_IMAGE` | Зафиксированный базовый образ Python для сборки |
| `LONGFAST_CHANNEL_INDEX` | Индекс основного канала, обычно 0 |
| `USB_DEVICE` | Стабильный путь к USB-порту на Pi; для работы только по BLE оставьте закомментированным |
| `MESHTASTIC_BLE_DEVICE` | Необязательный BLE-адрес; выбранная через интерфейс нода затем хранится в SQLite |
| `WEATHER_LOCATION` | Название города в интерфейсе и ответе на команду `w` |
| `WEATHER_LAT`, `WEATHER_LON` | Координаты погоды и начального центра карты |
| `LOCAL_TIMEZONE` | Часовой пояс IANA для команды `date` и времени погодной сводки |

В образце Москва указана как пример. Замените четыре параметра места и времени под свою сеть. Координаты принимают десятичные градусы; для часового пояса используйте имя вида `Europe/Moscow`. При изменении `.env` выполните `docker compose up -d`, чтобы контейнер получил новые значения.

## Запуск без Docker

На Linux откройте каталог проекта и установите Python-зависимости в отдельное виртуальное окружение:

```bash
python3.13 -m venv .venv
. .venv/bin/activate
python -m pip install -r requirements.txt
```

`venv` изолирует библиотеки проекта от системного Python; `pip` устанавливает закреплённую версию Meshtastic и её зависимости. Если создание окружения не удалось, установите пакет `python3.13-venv` для своей системы. Успех: после установки команда `python -c 'import meshtastic'` завершается без ошибки.

Подготовьте конфигурацию, если она ещё не создана:

```bash
test -f .env || cp .env.example .env
chmod 600 .env
nano .env
```

Замените `WEB_PASSWORD` и параметры города. Если значение содержит пробелы или символы оболочки, заключите его в кавычки, например `WEATHER_LOCATION="Название города"`. Для прямого запуска `USB_DEVICE` не нужен: порт выбирается в веб-интерфейсе из устройств Linux.

Загрузите переменные из `.env`, задайте доступный путь к SQLite и веб-порт, затем запустите приложение:

```bash
set -a
. ./.env
set +a
export DB_PATH="$PWD/data/messages.sqlite3"
export WEB_PORT=8766
python app.py
```

`set -a` экспортирует переменные из файла дочернему процессу; `DB_PATH` хранит историю в каталоге проекта вместо контейнерного пути `/data`. Каталог `data` приложение создаёт само. `WEB_PORT` задаёт порт прямого запуска; `MESHTASTIC_WEB_PORT` используется только Compose. Успешный запуск пишет `Web UI listening on 0.0.0.0:8766`; после этого откройте `http://<IP-АДРЕС-СЕРВЕРА>:8766/`. Остановить процесс можно клавишами `Ctrl+C`. Для доступа только с самого сервера задайте `WEB_HOST=127.0.0.1` до запуска.

По USB приложение показывает доступные `/dev/serial/by-id/`, `/dev/ttyACM*` и `/dev/ttyUSB*`. Пользователю нужны права на выбранный последовательный порт, обычно через группу `dialout`; проверьте владельца и группу командой `ls -l /dev/ttyACM0` или для вашего порта. Для Bluetooth нужен работающий BlueZ и системный D-Bus. Не запускайте контейнер и процесс Python одновременно с одной нодой или одним веб-портом. Команда `stats` при прямом запуске читает показатели из `/proc` и `/sys` хоста.

Если появился `ModuleNotFoundError`, активируйте `.venv` и повторите установку зависимостей. При `Permission denied` для USB проверьте права на порт; при `Address already in use` освободите порт или измените `WEB_PORT`. После закрытия терминала процесс останавливается: для постоянной работы запускайте его через менеджер служб вашей системы.

## Подключение ноды

### USB

Подключите ноду к Pi и найдите её порт:

```bash
ls -l /dev/serial/by-id/
ls -l /dev/ttyACM* /dev/ttyUSB* 2>/dev/null
```

Ожидаемый результат — ссылка в `/dev/serial/by-id/` и один из портов `ttyACM` или `ttyUSB`. При запуске через Docker укажите полный путь из `by-id` в `USB_DEVICE` внутри `.env`, затем примените его:

```bash
docker compose config --quiet
docker compose up -d
```

Compose передаёт выбранный порт в контейнер как `/dev/meshtastic`. При прямом запуске приложение находит порты хоста без проброса. В веб-интерфейсе откройте `Настройки → USB → Найти → Подключить`. Если список пуст, проверьте кабель, существование порта и права пользователя на него. После физического переподключения USB в Docker иногда требуется повторить `docker compose up -d`, чтобы контейнер заново открыл устройство.

### Bluetooth

На Pi проверьте BlueZ и системный D-Bus:

```bash
systemctl is-active bluetooth
ls -l /run/dbus/system_bus_socket
```

Первая команда должна вывести `active`, вторая — показать сокет. При запуске в контейнере приложение обращается к BlueZ через проброшенный сокет; без Docker оно использует системный D-Bus напрямую. В интерфейсе выберите `Настройки → Bluetooth → Найти`, затем ноду и `Подключить`. Если устройство требует сопряжения, сделайте его на Pi через `bluetoothctl` с PIN, который показывает нода. Телефонное приложение может удерживать BLE-соединение; при проблемах отключите его от ноды.

После успешного подключения форма поиска скрывается; остаются сведения о ноде и кнопка `Отключить`. Выбранное устройство запоминается в SQLite.

## Использование

### Чаты и каналы

Вкладка **Чаты** разделяет каналы и личные диалоги. LongFast — основной канал; `Создать канал` открывает окно для имени и ключа и занимает свободный слот на ноде. Для ключа используйте Base64: кнопка `Новый ключ` создаёт случайный 256-битный ключ. У Meshtastic не больше восьми слотов каналов на одной ноде. Настройки выбранного канала, включая его текущий ключ, открываются кнопкой `Конфигурация`.

Пример `AQ==` — общедоступное короткое обозначение стандартного ключа Meshtastic, а не секрет проекта. Ключи ваших реальных каналов держите вне GitHub.

Личную переписку можно открыть из списка нод или по ID вида `!1234abcd`. Непрочитанные сообщения выделяются и считаются отдельно по чатам. При входе показывается первое непрочитанное; при прокрутке к последнему сообщению вся переписка отмечается прочитанной. Правый клик по сообщению, а на телефоне долгое нажатие, открывает ответ и каталог реакций.

Отметка «Доставлено» в личке появляется после ACK адресата. Подтверждение ретранслятора и отсутствие подтверждения показываются отдельно; отправка в радио сама по себе не означает доставку.

### Команды бота

Бот реагирует **только на входящие личные сообщения**. Сравнение шаблонов не учитывает регистр и пробелы по краям; шаблон имеет приоритет над встроенной командой. На произвольные сообщения без шаблона бот не отвечает.

| Сообщение | Ответ |
| --- | --- |
| `ping` или `p` | Число хопов до отправителя и SNR/RSSI принятого запроса. Уровень сигнала относится к последнему радиопереходу; при отсутствии метрик бот пишет «нет данных» |
| `trace` | Трассировка маршрута до отправителя и результат в личке |
| `stats` | Краткая статистика Pi: CPU, RAM, температура, диск, время работы |
| `w` или `W` | Погода для города из `.env` |
| `date` | Дата и время в `LOCAL_TIMEZONE` |

В **Настройках** можно выключить все ответы бота или добавить собственные шаблоны. Команды и шаблоны не работают в LongFast и дополнительных каналах. Запросы трассировки ограничены паузой 35 секунд; ответ может ждать до трёх минут.

### Ноды и настройки радио

Список нод показывает данные NodeDB подключённого устройства. Поиск работает по имени и ID; карточка ноды содержит доступные показатели связи, батареи, телеметрии и координаты. Карта начинает показ с координат `WEATHER_LAT` и `WEATHER_LON` и может вместить все ноды с известной позицией.

Настройки радио читаются с подключённой ноды. Веб-интерфейс позволяет менять доступные поля устройства, LoRa, геопозиции, питания, экрана, Bluetooth, MQTT и каналов. Изменение LoRa, BLE или каналов может прервать соединение. Приватные и административные ключи ноды через веб-интерфейс не редактируются.

## Данные и резервная копия

Сообщения, шаблоны, состояние прочтения, выбранная нода и трассировки хранятся в SQLite. В Docker база лежит в именованном томе `meshtastic-data`, при прямом запуске — по пути `DB_PATH`. История и реальные ключи в репозиторий не входят. После переподключения бот импортирует доступные ноде текстовые пакеты без дублей и без повторных автоответов. Нода может не хранить всю прошлую историю, поэтому пропущенные ею пакеты восстановить нельзя.

После обновления файлов проекта пересоберите контейнер из каталога проекта:

```bash
docker compose config --quiet
docker compose up -d --build
docker compose ps
```

`up -d --build` пересобирает сервис и сохраняет именованный том. Для обычного обновления **не применяйте** `docker compose down -v`: флаг `-v` удаляет том и переписку.

Перед крупными изменениями сохраните резервную копию SQLite. Для Docker встроенный механизм SQLite создаёт согласованный снимок даже при работающем сервисе:

```bash
docker compose exec meshtastic python -c 'import sqlite3; src=sqlite3.connect("/data/messages.sqlite3"); dst=sqlite3.connect("/data/messages.backup.sqlite3"); src.backup(dst); dst.close(); src.close()'
docker compose cp meshtastic:/data/messages.backup.sqlite3 ./messages.backup.sqlite3
```

При прямом запуске, когда `DB_PATH` уже экспортирован, создайте снимок так:

```bash
python -c 'import os, sqlite3; src=sqlite3.connect(os.environ["DB_PATH"]); dst=sqlite3.connect("messages.backup.sqlite3"); src.backup(dst); dst.close(); src.close()'
```

Копию `messages.backup.sqlite3` перенесите на другой носитель: файл в каталоге проекта не защитит от отказа его диска. Резервные копии исключены из Git. При ошибке проверьте свободное место командой `df -h` и журнал приложения.

## Диагностика

```bash
docker compose ps
docker compose logs --tail=80 meshtastic
```

`ps` показывает состояние контейнера; `logs` — причину ошибки приложения или связи. Если контейнер перезапускается, проверьте пароль в `.env`, существование пути `USB_DEVICE` и права на устройство. Если сайт открывается, но нода не находится, начните с USB-порта или состояния BlueZ. Если погода недоступна, проверьте исходящий HTTPS к `wttr.in` и координаты в `.env`. Если карта пустая, проверьте, передавали ли ноды GPS-координаты и доступен ли OpenStreetMap в браузере.

## Безопасность

- Не добавляйте в Git `.env`, базу SQLite, журналы, резервные копии, настоящие ключи каналов и снимки экрана с ними.
- Веб-интерфейс использует HTTP Basic Auth. HTTP не шифрует пароль и переписку в сети. Используйте доверенную локальную сеть или собственный HTTPS reverse proxy; не делайте прямой проброс порта в интернет.
- Эндпоинт `/metrics` открыт без авторизации для локального мониторинга. Он отдаёт только статус соединения и число нод, но всё равно доступен любому устройству, имеющему доступ к порту.
- Доступ к веб-интерфейсу позволяет отправлять сообщения и менять настройки радио. Выбирайте отдельный длинный пароль.
