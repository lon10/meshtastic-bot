# Mesh Radio Bot

**Локальный веб-интерфейс и бот для Meshtastic на Raspberry Pi.** Подключается к ноде через USB или Bluetooth, хранит переписку в SQLite и отвечает на команды только в личных сообщениях.

> Проект сообщества, не официальный клиент Meshtastic. По умолчанию веб-интерфейс доступен в локальной сети по HTTP. Не публикуйте его напрямую в интернете.

## Что умеет

| Раздел | Возможности |
| --- | --- |
| Чаты | Общий канал LongFast, дополнительные каналы и личные диалоги; отправка, цитирование, реакции и поиск эмодзи |
| История | SQLite, счётчики непрочитанных, статусы доставки, импорт доступных сообщений после переподключения |
| Ноды | Поиск, карточки с телеметрией, координатами и качеством связи, карта и история трассировок |
| Бот | Шаблоны «запрос → ответ», команды ping, trace, stats, w и date; отвечает только в личке |
| Радио | Подключение по USB или BLE, просмотр и изменение поддерживаемых настроек ноды и каналов |
| Веб-интерфейс | Вкладки «Дашборд», «Чаты», «Настройки», адаптивная мобильная версия, вход по логину и паролю |

Стек: **Python 3.13**, **Meshtastic Python 2.7.11**, стандартные модули **http.server** и **sqlite3**, обычный JavaScript без сборщика, **Leaflet 1.9.4**, **Docker Compose**. Код сервера находится в **app.py**, клиентская логика — в **app.js**, интерфейс — в **index.html**.

## Требования

- Raspberry Pi с 64-битной Linux-системой, Docker Engine и плагином Docker Compose.
- Нода Meshtastic с настроенным регионом и антенной. Перед включением передачи убедитесь, что регион в ноде выбран правильно.
- Для USB: кабель передачи данных и последовательный порт вида **/dev/serial/by-id/...** или **/dev/ttyACM0**.
- Для BLE: работающий Bluetooth и BlueZ на хосте.
- Для погоды: исходящий HTTPS-доступ с Pi к **wttr.in**. Для подложки карты браузеру нужен доступ к OpenStreetMap.

Проверка Docker на Pi:

~~~bash
docker --version
docker compose version
~~~

Обе команды должны вывести версии. Если команда не найдена, установите Docker Engine и Compose для вашей системы перед запуском проекта. На системах, где пользователь не входит в группу **docker**, используйте **sudo docker** в командах ниже.

## Быстрый запуск

Скопируйте папку проекта на Pi или клонируйте свой будущий репозиторий GitHub. Все дальнейшие команды выполняются **на Pi** из папки проекта:

~~~bash
cp .env.example .env
chmod 600 .env
nano .env
~~~

**cp** создаёт личную конфигурацию из образца; **chmod 600** разрешает читать её только владельцу; **nano** открывает файл для редактирования. Замените значение **WEB_PASSWORD** на длинный случайный пароль. Его можно создать командой **openssl rand -base64 32** и вставить в **.env**. Настройте город, координаты и часовой пояс. Файл **.env** исключён из Git и Docker build context.

~~~bash
sudo docker compose config --quiet
sudo docker compose up -d --build
sudo docker compose ps
~~~

**config --quiet** проверяет Compose и переменные, не печатая пароль. **up -d --build** собирает образ и запускает контейнер в фоне. **ps** должен показать сервис **meshtastic** со статусом **Up** и портом **8766 → 8765**. Откройте в браузере компьютера или телефона в той же сети:

~~~text
http://<IP-АДРЕС-PI>:8766/
~~~

Введите **WEB_USER** и **WEB_PASSWORD** из своего **.env**. Если Pi доступен по mDNS, вместо IP можно использовать его локальное имя, например **raspberrypi.local**. Порт **8766** меняется через **MESHTASTIC_WEB_PORT**.

### Настройки .env

| Переменная | Назначение |
| --- | --- |
| **WEB_USER**, **WEB_PASSWORD** | Учётная запись для HTTP Basic Auth; пароль обязательно замените |
| **MESHTASTIC_WEB_PORT** | Порт на Pi для браузера, по умолчанию 8766 |
| **PYTHON_IMAGE** | Зафиксированный базовый образ Python для сборки |
| **LONGFAST_CHANNEL_INDEX** | Индекс основного канала, обычно 0 |
| **USB_DEVICE** | Стабильный путь к USB-порту на Pi; для работы только по BLE оставьте закомментированным |
| **MESHTASTIC_BLE_DEVICE** | Необязательный BLE-адрес; выбранная через интерфейс нода затем хранится в SQLite |
| **WEATHER_LOCATION** | Название города в интерфейсе и ответе на команду **w** |
| **WEATHER_LAT**, **WEATHER_LON** | Координаты погоды и начального центра карты |
| **LOCAL_TIMEZONE** | Часовой пояс IANA для команды **date** и времени погодной сводки |

Образец содержит **Москву только как пример**. Замените четыре параметра места и времени под свою сеть. Координаты принимают десятичные градусы; для часового пояса используйте имя вида **Europe/Moscow**. При изменении **.env** выполните **sudo docker compose up -d**, чтобы контейнер получил новые значения.

## Подключение ноды

### USB

Подключите ноду к Pi и найдите её порт:

~~~bash
ls -l /dev/serial/by-id/
ls -l /dev/ttyACM* /dev/ttyUSB* 2>/dev/null
~~~

Ожидаемый результат — ссылка в **/dev/serial/by-id/** и один из портов **ttyACM** или **ttyUSB**. Укажите полный путь из **by-id** в **USB_DEVICE** внутри **.env**, затем примените его:

~~~bash
sudo docker compose config --quiet
sudo docker compose up -d
~~~

Compose передаёт выбранный порт в контейнер как **/dev/meshtastic**. В веб-интерфейсе откройте **Настройки → USB → Найти → Подключить**. Если списка устройств нет, проверьте, что кабель передаёт данные, путь **USB_DEVICE** существует и порт не занят другой программой. После физического переподключения USB иногда требуется повторить **up -d**, чтобы Docker заново открыл устройство.

### Bluetooth

На Pi проверьте BlueZ и системный D-Bus:

~~~bash
systemctl is-active bluetooth
ls -l /run/dbus/system_bus_socket
~~~

Первая команда должна вывести **active**, вторая — показать сокет. Контейнер обращается к BlueZ через этот сокет. В интерфейсе выберите **Настройки → Bluetooth → Найти**, затем ноду и **Подключить**. Если устройство требует сопряжения, сделайте его на Pi через **bluetoothctl** с PIN, который показывает нода. Телефонное приложение может удерживать BLE-соединение; при проблемах отключите его от ноды.

После успешного подключения форма поиска скрывается; остаются сведения о ноде и кнопка **Отключить**. Выбранное устройство запоминается в SQLite.

## Использование

### Чаты и каналы

Вкладка **Чаты** разделяет каналы и личные диалоги. LongFast — основной канал; **Создать канал** открывает окно для имени и ключа и занимает свободный слот на ноде. Для ключа используйте Base64: кнопка **Новый ключ** создаёт случайный 256-битный ключ. У Meshtastic не больше восьми слотов каналов на одной ноде. Настройки выбранного канала, включая его текущий ключ, открываются кнопкой **Конфигурация**.

Пример **AQ==** — общедоступное короткое обозначение стандартного ключа Meshtastic, а не секрет проекта. Ключи ваших реальных каналов держите вне GitHub.

Личную переписку можно открыть из списка нод или по ID вида **!1234abcd**. Непрочитанные сообщения выделяются и считаются отдельно по чатам. При входе показывается первое непрочитанное; при прокрутке к последнему сообщению вся переписка отмечается прочитанной. Правый клик по сообщению, а на телефоне долгое нажатие, открывает ответ и каталог реакций.

Отметка **«Доставлено»** в личке появляется после ACK адресата. Подтверждение ретранслятора и отсутствие подтверждения показываются отдельно; отправка в радио сама по себе не означает доставку.

### Команды бота

Бот реагирует **только на входящие личные сообщения**. Сравнение шаблонов не учитывает регистр и пробелы по краям; шаблон имеет приоритет над встроенной командой. На произвольные сообщения без шаблона бот не отвечает.

| Сообщение | Ответ |
| --- | --- |
| **ping** | Число хопов до отправителя по доступным сведениям ноды |
| **trace** | Трассировка маршрута до отправителя и результат в личке |
| **stats** | Краткая статистика Pi: CPU, RAM, температура, диск, время работы |
| **w** или **W** | Погода для города из **.env** |
| **date** | Дата и время в **LOCAL_TIMEZONE** |

В **Настройках** можно выключить все ответы бота или добавить собственные шаблоны. Команды и шаблоны не работают в LongFast и дополнительных каналах. Запросы трассировки ограничены паузой 35 секунд; ответ может ждать до трёх минут.

### Ноды и настройки радио

Список нод показывает данные NodeDB подключённого устройства. Поиск работает по имени и ID; карточка ноды содержит доступные показатели связи, батареи, телеметрии и координаты. Карта начинает показ с координат **WEATHER_LAT/WEATHER_LON** и может вместить все ноды с известной позицией.

Настройки радио читаются с подключённой ноды. Веб-интерфейс позволяет менять доступные поля устройства, LoRa, геопозиции, питания, экрана, Bluetooth, MQTT и каналов. Изменение LoRa, BLE или каналов может прервать соединение. Приватные и административные ключи ноды через веб-интерфейс не редактируются.

## Данные, обновление и резервная копия

Сообщения, шаблоны, состояние прочтения, выбранная нода и трассировки хранятся в SQLite в именованном томе **meshtastic-data**. Папка проекта содержит только исходный код и пример конфигурации; история и реальные ключи в репозиторий не входят. После переподключения бот импортирует доступные ноде текстовые пакеты без дублей и без повторных автоответов. Нода может не хранить всю прошлую историю, поэтому пропущенные ею пакеты восстановить нельзя.

Для обновления исходников в своей копии репозитория:

~~~bash
git pull
sudo docker compose config --quiet
sudo docker compose up -d --build
sudo docker compose ps
~~~

**git pull** получает новые файлы, **up -d --build** пересоздаёт сервис и сохраняет именованный том. Для обычного обновления **не применяйте** **docker compose down -v**: флаг **-v** удаляет том и переписку.

Перед крупными изменениями сохраните резервную копию SQLite. Встроенный механизм SQLite создаёт согласованный снимок даже при работающем сервисе:

~~~bash
sudo docker compose exec meshtastic python -c 'import sqlite3; src=sqlite3.connect("/data/messages.sqlite3"); dst=sqlite3.connect("/data/messages.backup.sqlite3"); src.backup(dst); dst.close(); src.close()'
sudo docker compose cp meshtastic:/data/messages.backup.sqlite3 ./messages.backup.sqlite3
~~~

Первая команда создаёт снимок в томе, вторая копирует его в папку проекта. Файл исключён из Git, но хранится на той же Pi; для защиты от отказа SD-карты перенесите его на другой носитель. При ошибке проверьте **sudo docker compose logs --tail=80 meshtastic** и свободное место командой **df -h**.

## Диагностика

~~~bash
sudo docker compose ps
sudo docker compose logs --tail=80 meshtastic
~~~

**ps** показывает состояние контейнера; **logs** — причину ошибки приложения или связи. Если контейнер перезапускается, проверьте пароль в **.env**, существование пути **USB_DEVICE** и права на устройство. Если сайт открывается, но нода не находится, начните с USB-порта или состояния BlueZ. Если погода недоступна, проверьте исходящий HTTPS к **wttr.in** и координаты в **.env**. Если карта пустая, проверьте, передавали ли ноды GPS-координаты и доступен ли OpenStreetMap в браузере.

## Безопасность

- Не добавляйте в Git **.env**, базу SQLite, журналы, резервные копии, настоящие ключи каналов и снимки экрана с ними.
- Веб-интерфейс использует HTTP Basic Auth. HTTP не шифрует пароль и переписку в сети. Используйте доверенную локальную сеть или собственный HTTPS reverse proxy; не делайте прямой проброс порта в интернет.
- Эндпоинт **/metrics** открыт без авторизации для локального мониторинга. Он отдаёт только статус соединения и число нод, но всё равно доступен любому устройству, имеющему доступ к порту.
- Доступ к веб-интерфейсу позволяет отправлять сообщения и менять настройки радио. Выбирайте отдельный длинный пароль.

## Публикация своей копии на GitHub

Создайте на GitHub пустой репозиторий **без автоматически созданных README и LICENSE**, затем в распакованной папке проекта выполните:

~~~bash
git init
git add .
git status --short
git commit -m "Initial release"
git branch -M main
git remote add origin https://github.com/ACCOUNT/REPOSITORY.git
git push -u origin main
~~~

Замените **ACCOUNT/REPOSITORY** на адрес своего репозитория. **git status --short** показывает точный список добавляемых файлов: убедитесь, что там есть **.env.example**, но нет **.env**, баз SQLite, журналов или резервных копий. После публикации проверьте список файлов и историю коммитов на GitHub. Если настоящий секрет когда-либо попал в коммит, удаление файла из следующего коммита не отменяет утечку: смените этот секрет и очистите историю до публикации.
